# frontend-config

状态：已确认。上级：[架构与组装](../架构与组装.md)。

## 1. 职责

- 负责：编辑和保存全部配置（[C06](../契约/C06-配置模型.md)）：实体、页面（字段设置、按钮、拖动编辑表单布局）、操作、规则、审批流、角色、菜单、字典、Lookup、导出；保存前校验，把错误定位到配置的具体位置。
- 不负责：配置的校验规则和保存（config）。

## 2. 所有权

| 类别 | 内容 |
|---|---|
| 代码 | `frontend/src/modules/config/` |
| 状态 | 配置编辑界面的状态 |

## 3. 对外契约

导出 C11 的 `FrontendModule`，路由 `/config`；调用 [C09 第 3 节](../契约/C09-HTTP接口.md)的接口。

- FC-01：只对管理员角色显示。
- FC-02：保存即生效；保存前可以先调用校验接口，校验错误定位到配置的具体路径。C06 第 1.1 节要求必须写的字段（例如页面的 `audit`、操作的 `propagation`），新建时由编辑界面预填，保存时总是带上。
- FC-03：表单布局用 24 列网格拖动编辑（grid-layout-plus），保存后所有人共用。
- FC-04：行权限的编辑界面与旧系统一致：可视化条件和自定义 SQL 两种方式。
- FC-05：审批流编辑覆盖 C06 第 7 节的全部配置项，位置、布局、表格和弹窗的样式与旧系统页面配置中的"审批流"一致（旧项目 `SectionApproval.vue` 及其弹窗，用户 2026-10-28 确认《审批流配置定稿》，样稿 `.reports/approval-design/审批流配置样稿-旧版样式.html`）：
  - 流程列表（AG Grid，可直接编辑）：流程名称、所属页面（只读）、审核操作、启用、顺序。"审核操作"点开"哪些保存操作触发送审"弹窗：列出本页面的表格，每张勾新增、修改、删除；列表中显示为"原辅料.新增、原辅料.修改"。工具栏：新增流程、保存并发布当前流程、校验配置、删除／停用、刷新。
  - Tab"审批节点"：级别、节点名称、条件类型（始终满足 / SQL 条件）、入口条件、发起部门限制、人员 / 角色 / SQL、同级方式（或签 / 会签）、启用。入口条件双击打开编辑弹窗，沿用旧系统"来源 / 表 / 字段 + 插入参数"的选择方式插入 C06 7.2 的参数；审批人弹窗沿用旧系统的写法（人员、角色、SQL 选人）。
  - Tab"冻结节点"：启用、冻结表、关联条件。冻结表可以直接写表名。
  - Tab"展示数据"：展示标题、展示区域、展示表 / 视图、关联条件、修改的表、主键列、显示列、勾选方式、审批通过后的操作。修改内容的展示表从本页面表格中选，受影响单据可以直接写表名或视图名；写好后经 C09 的 `POST /api/config/schema/columns` 读出列，供显示列、主键列、写入字段选择。显示列弹窗沿用旧系统"审批展示 · 列映射"，列为字段、显示名称、小数位、列宽、对应修改表的列；通过后的操作弹窗沿用旧系统"审批通过后写入的字段"，列为写入字段、取值。
  - 参数和通知照旧。保存前经 `POST /api/config/validate` 校验，把错误定位到具体的行和格子。
- FC-06：规则和旧系统一样按表单编辑：规则类型、作用字段、条件（可视化条件或表达式）、计算表达式和分支（C06 第 5 节）；不做图形化的规则编辑器。
  - 条件中的字符串常量与后端 `config/expressions.py` 相同：ZEN 的字符串没有转义，含单引号的文字用双引号括起，其余用单引号。
  - 校验规则的"必填"用于数值字段时不生成条件（rules-core 中数值为空按 0 计算，`PRICE == null` 永远不成立），按钮为"设为字段必填"：这张卡片换成"字段必填"，保存为字段设置的 `required`，层级"实体"写实体的 `fieldDefaults`（所有页面），"本页面"写页面区域的字段设置，"操作"不能换。保存单据时写入管道按真实的值检查（write-pipeline 的 WP-07：为空时拒绝，提示"单价 不能为空"，0 可以保存），同旧系统 `validator.ts` 的 `validateRow`。弹窗中列出这个区域已有的字段必填（实体默认、本页面），可以删除；它与"表与列"的"必填"列是同一个设置，保存后"表与列"重新读取。文本等字段的"必填"仍生成条件 `X == null or X == ''`。"规则"选择只用来生成条件：新卡片默认"必填"，已经写了条件的卡片显示为"自定义"（条件就是写好的那一条）。
- FC-07：新建页面向导：选择上级菜单、填写页面名称和编码、选择单表或主从；选择主表的视图和写入表，导入列并调整标题、可见、可编辑；添加明细表并指定关联列；页面的审计和明细显示方式由界面预填，审计默认开启（`audit` 为 true），明细显示方式默认多 Tab（`detailMode` 为 `tabs`），管理员确认或修改后随生成请求提交，单表页不显示明细显示方式、按预填值提交；预览后生成（config CF-14，同时生成页面的保存操作）。序列不存在时提示用户先建序列。
- FC-08：实体编辑中可以配置必须审批的字段规则、默认值和对比；审批流编辑中可以配置 SQL 审批人和审批人填写的参数（各级审批人填写的参数在最终批准时使用）。
- FC-09：页面配置"表与列"的字段表，"显示、编辑、必填"显示实际结果（用户 2026-10-29 指出配置上全是可编辑、页面上却基本不能编辑）：
  - 字段本身不能编辑的（计算字段、系统字段、只在视图中没有写入列的、没有 `erpRow` 的实体的 ERP 列、`erpRow.column`，C06 第 2 节），编辑格不勾、不能改。
  - "本页面"范围下，实体默认已设为不显示、不可编辑或必填的字段，对应格子不能改（下层只能收紧可见、可编辑，必填只能增加），要改须切到"实体默认"。
  - 不能改的格子在"不能修改的原因"列和悬停提示中写明原因，例如"实体默认不可编辑（所有页面），切到“实体默认”修改"。角色的列权限（C06 第 8 节）还会再收紧，表中不计算，只给一句提示。
  - 保存的内容格式不变，只写本层需要写的设置。
  - "保存列"依次保存实体、页面和页面保存操作（`saveOperation`），每一步都先校验，哪一步不通过就停在哪一步。保存操作的 `writableFields` 按 config CF-14 的规则，对本页面的主表和每个明细实体重算，再加上可编辑字段的 Lookup 回填目标中有写入列的（authz 的 AZ-04）。只改 `writableFields`，其他实体的可写字段和操作的其他内容不变；没有变化时不保存。"实体默认"范围保存时，同样重算本页面的保存操作。页面视图的 `editable` 与 `writableFields` 取交集（C05），所以重算后页面上能编辑的字段与这张表一致（角色收紧的除外）。
- FC-10："表与列"的字段表有"求和"勾选列，同旧系统 `SectionTables.vue` 的"求和"（`rulesConfig.aggFunc`）：勾选时保存为本页面字段设置的 `aggregate: "sum"`（C06 第 3 节），页面上这一列在底部汇总行中求和（frontend-page 的 FP-17）。只有数值字段能勾；"本页面"和"实体默认"两个范围下都是本页面的设置。
- FC-12：角色权限的"配置按钮"对话框（C06 v24 第 8 节，用户 2026-10-30"权限可以按照新增 删除 修改 保存 这样给吗？控制到明细级别"，样子接近用户附图里的一排勾选框）。勾"全部按钮"时保存为 `["*"]`；否则从上到下：
  - "页面"：保存、高级查询（`system:save`、`system:advancedSearch`）；
  - "新增、删除、修改"：一行一个区域，第一行"主表"，其后每个明细一行，标题取页面配置中明细的标题（例如成本核算为"主表""原料/辅料""包材"；单表页只有"主表"）；每行三个勾选框"新增""删除""修改"（`<区域>:addRow`、`<区域>:deleteRow`、`<区域>:modify`）；标题旁写明"没有'修改'时这个区域已保存的行都不能改，新增的行照常填写"；
  - 各区域的其余按钮（复制、由BOM生成明细、保存列配置等，分组标题为"主表"和明细标题），按页面配置的顺序，页面配置里的新增、删除不在这里重复；
  - "导出"：本页面的导出配置（`export:<编码>`）。
  按钮分组参考旧系统权限页（`cost-web/src/views/_builtin/permission/index.vue`）。代码在 `role/role-model.ts`（`PAGE_BUTTONS`、`areaPermissionRows`、`buttonGroups`）和 `role/RoleButtonDialog.vue`。
- FC-11："表与列"的表信息中有"修改人列"，对应实体的 `updatedByColumn`（C06 第 2 节，2026-10-30 按旧系统每次保存写 UPDATE_BY 加入）：填目标表中的列名，例如物料清单填 UPDATE_BY；清空时去掉这一项。随"保存表信息"保存，保存时由 config 校验列在表中、不是字段的列。
- FC-16：菜单图标（C06 v26 菜单项的 `icon`）在两处选：页面"基本信息"的"图标"（同旧系统 `SectionBasicInfo.vue` 第 33–54、87–96 行），改的是这个页面所在的菜单项，点"保存"时先保存页面、图标改了再保存菜单配置项，页面没有挂在菜单下时不能选；"目录信息"的"图标"，改的是选中的分组或配置、管理入口（旧目录信息只显示图标，新平台这里本来就能改分组名称，图标一起改；配置、管理入口也打开目录信息，只改名称和图标）。下拉的选项是旧系统的 20 个常用图标，可以输入别的 Iconify 图标名（例如旧菜单资源的 `mdi:domain`），清空即去掉 `icon`（外壳用默认图标）。代码在 `views/menu-tree.ts`（`ICON_OPTIONS`、`setNodeIcon`、`menuItemOfPage`）、`SectionBasicInfo.vue`、`DirectoryInfoPanel.vue`。
- FC-13："表与列"的字段表有"查询"勾选列，同旧系统 `SectionTables.vue` 第 79–82 行的"查询"（`searchable`）：勾选时保存为本页面字段设置的 `searchable: true`（C06 v23 第 3 节），不勾时不写；页面上高级查询对话框一打开就列出这个字段的条件（frontend-page 的 FP-22）。任何类型的字段都能勾；"本页面"和"实体默认"两个范围下都是本页面的设置，同"求和"。
