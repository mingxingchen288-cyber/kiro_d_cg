# frontend-page

状态：已确认。上级：[架构与组装](../架构与组装.md)。

## 1. 职责

- 负责：按页面视图（[C05](../契约/C05-页面视图.md)）渲染单表页和主从页；原地表单；编辑缓冲；在 Worker 中本地预览；保存和局部刷新；Lookup、字典、高级查询、按钮；个人列配置；冻结和审批中状态的显示；配置变更后原地替换。
- 不负责：外壳和页签（frontend-shell）；表单布局的编辑（frontend-config）；审批界面（frontend-approval）。

## 2. 所有权

| 类别 | 内容 |
|---|---|
| 代码 | `frontend/src/modules/page/`：page-runtime、grid-adapter（唯一引用 AG Grid 的部分）、edit-buffer、view-model、preview（经 `ShellApi.calc` 调用计算 Worker；Worker 由 rules-core 交付，assembly 创建实例）、renderers |
| 状态 | 每个页面实例的编辑缓冲、预览结果和界面状态，不跨模块共享 |

## 3. 对外契约

导出 C11 的 `FrontendModule`，路由 `/page/:pageCode`；调用 [C09](../契约/C09-HTTP接口.md) 第 3–5 节的接口和 [C07](../契约/C07-规则内核接口.md) 的 Worker 消息。

- FP-01：单表页只有主表区；主从页在主表区下面显示明细区，明细按 Tab 或堆叠显示，分隔线可以拖动。旧系统的主从嵌套模式不保留。
- FP-02：主表用 AG Grid 服务端行模型，明细用客户端行模型。行标识用 `rowKey` 或 `clientRowId`；新增行保存后换成正式主键，行节点不变。
- FP-03：每行最前面固定一列展开图标。点击后，表单在主表区原地替换表格显示：表格只设为不可见，滚动位置和选中行保留；明细区不动。表单头部有返回、上一条、下一条。双击单元格照常进入单元格编辑。
- FP-04：编辑缓冲按页面实例维护：修改值、新增行、删除标记、改动标记（沿用旧样式）、撤销和重做（表格和表单共用，关闭 AG Grid 自带的撤销）。保存时把全部修改生成一个命令（C02）。
- FP-05：编辑后在 Worker 中按 preview 阶段求值，请求中的 `old` 取编辑缓冲中的已提交值（从后端加载到的值），只刷新受影响行的单元格；预览结果只用于显示。
- FP-06：点击保存：生成新的请求键 → 整页只读并显示保存中 → 提交命令。成功时用结果逐行比对，只更新有差异的行（主表用 `applyServerSideTransaction`，明细用 `applyTransaction`），按 `idMap` 换主键；结果中缺的行用按主键取行补查，影响范围不明时只重查当前页；然后清空编辑缓冲，恢复编辑。失败或没有收到响应时，恢复编辑，保留全部修改，按错误的 `details` 定位到行和字段；不自动重发。
- FP-07：结果为已提交审批时，按 `approvals` 提示哪些单据进入审批，这些单据整张显示正式数据（本次新增的行从表格中移除，删除的行保留，修改恢复为原值），其余单据按写入结果刷新；被冻结的单据整张只读（主从页为主表和全部明细，不能新增或删除明细；单表页为整行），并显示冻结它的审批；点击或试图修改时弹出该审批的进度（FP-16）。
- FP-08：增删改查都不整页刷新，也不重建表格；查询后列宽、顺序、固定和显隐不变。
- FP-09：收到 `config.changed` 后，重新读取页面视图，原地替换列、表单布局、按钮和规则包；正在编辑的值保留。这些请求是后台请求（C09 第 1 节），不顺延会话。
- FP-10：不可见的字段不显示在列、表单和列工具面板中，但数据仍保留在行里，供预览使用。
- FP-11：个人列配置（列宽、顺序、固定、显隐、明细显示方式）经 C09 读写；上层隐藏的列不能被设为显示。
- FP-12：有未保存修改时，关闭页签、刷新或离开页面前先确认。
- FP-14：工具栏和右键菜单按页面视图的 `systemButtons` 和各区域的 `buttons` 显示按钮：新增、删除只在页面配置放了这两个按钮的区域显示，且需要 `systemButtons` 含对应项；没有选中行时，删除和其他 `requiresSelection` 为 true 的按钮不可用，新增照常可用（config 的 CF-03）；没有 `save` 时整页只读。业务按钮的命令只带选中行的主键（`params.selectedRows`），不带编辑缓冲中的值，也不带页面上没保存的修改（C02 第 1 节）。页面有没保存的修改时也直接执行，不提示先保存。成功后按命令结果的 `rows` 刷新受影响的行：这些行显示后端返回的值，编辑缓冲中这些行没保存的修改丢弃；其他行没保存的修改（包括还没保存的新增行）保留。失败时编辑缓冲不变。
- FP-15：新增行时按字段的 `default` 填值（C06 第 2 节）；`options` 字段用下拉选择。Lookup 按 C06 第 3 节的 `multiple`、`filter`、`fillBack` 处理；对话框打开时先用空关键字查询，响应的 `keywordSearch` 为 false 时不显示搜索框（C09 第 4 节）。字段有 `compare` 时，在值旁显示差值或百分比，上升和下降用不同的箭头和颜色，与旧系统相同。
- FP-16：用户修改被审批锁定的单据时，直接弹窗显示锁定它的审批进度，不进入编辑：
  - 行带 `frozen` 时（C09 的 `DataRow`、C02 的 `rows[].frozen`），双击单元格、在表单中修改、粘贴、删除行、给这张单据新增明细，都不改编辑缓冲，直接弹出 `frozen.approvalId` 的审批进度。
  - 保存或按钮操作返回 409 FROZEN_BY_APPROVAL 时（例如页面加载后单据才被锁定，或改到了只锁定、审批后不更新的单据），按错误明细的 `approvalId` 弹出审批进度，有几个审批就分别列出；编辑缓冲按 FP-06 保留。明细中没有 `approvalId` 时（同一次保存中的两张单据要锁定同一张单据，approval AP-06），照常显示错误提示。
  - 进度经 `GET /api/approvals/{approvalId}` 读取（C09 第 6 节，任何已登录的用户都能查看）。弹窗显示来源页面、来源单据号、提交人、提交时间、当前级别和各级入口的处理情况（`steps`），不显示修改内容，也不能在这里通过或驳回。
- FP-13：复制，只在区域的 `buttons` 含 `copyRow` 时提供（C05）。
  - 复制对话框：主表区复制一行时，可以勾选要复制的主表字段，以及每个明细 Tab 要复制的行和字段；明细区复制时，可以勾选要复制的行（默认是表格中选中的行）和字段。默认全选，与旧系统相同。
  - 只有主键不复制；明细的主从关联字段指向新的主表行；没勾选的字段留空。复制的是当前显示的值（含未保存的修改），标为删除的行不复制；源单据的明细还没加载时，先按单据加载接口读取。
  - 计算字段照样复制显示，随后由预览重新计算；生成命令时按 C02 不带计算字段，保存时以后端的计算为准。`erpRow.column` 由平台设为本地，不从源行复制；ERP 列照样复制，新行是本地行，可以编辑。
  - 复制出的主表行放在源行下方，明细行放在最后一个选中行的下方；复制结果只在编辑缓冲中，保存后才写入；撤销一次即撤回整个复制。

## 4. 依赖

契约 C01、C02、C03、C05、C07、C09、C10、C11；预览只经 `ShellApi.calc` 调用，不直接引用 rules-core 的产物。

## 5. 内部流程

编辑：编辑缓冲记录修改 → Worker 求值 → view-model 更新受影响行 → grid-adapter 刷新这些行。保存：见 FP-06。

## 6. 接入方式

注册到外壳（C11），由 assembly 完成。真实联调：批次 D。

## 7. 验收边界

- 开始开发的前置条件：contracts 完成；计算 Worker 先用 contracts 提供的模拟实现。
- 本模块完成（模拟验证）：用 C09 的模拟实现验证编辑、预览、保存、局部刷新、失败保留修改、冻结只读和配置变更后的原地替换。
- 联调后才能确认：连接真实后端后，保存后的数据与数据库一致，前端预览与后端计算结果一致（批次 D）。
