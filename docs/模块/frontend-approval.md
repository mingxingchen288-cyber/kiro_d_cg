# frontend-approval

状态：已确认。上级：[架构与组装](../架构与组装.md)。

## 1. 职责

- 负责：待办列表（我审批的、我发起的）；审批详情（来源的修改前后、各级进度、影响对象的修改前后和勾选框、意见）；通过、驳回、撤回；重新确认的提示。
- 不负责：审批的判断和执行（approval）。

## 2. 所有权

| 类别 | 内容 |
|---|---|
| 代码 | `frontend/src/modules/approval/` |
| 状态 | 待办和审批详情的界面状态 |

## 3. 对外契约

导出 C11 的 `FrontendModule`，路由 `/approval`；调用 [C09 第 6 节](../契约/C09-HTTP接口.md)的接口。

- FA-01：影响对象每行一个勾选框，按行的 `checked` 显示，默认全选；块的 `editable` 为 true 时审批人可以取消，否则勾选框不能改。通过时把这次取消的行放进 `uncheckedRows`（带 `flow`、`block`），带上结果指纹和新的请求键。
- FA-02：不显示排队：同一张单据同一时间只在一个审批中（approval AP-06）。
- FA-03：收到 409 RECONFIRM_REQUIRED 时，重新读取详情，请审批人再次确认。
- FA-04：只有 `canWithdraw` 为 true 时显示"撤回"。
- FA-05：通知中的链接 `/approval/{approvalId}` 直接打开审批详情。
- FA-06：一张单据的审批只显示一次，几个审批流合在一起显示（C09 第 6 节）。待办列表每个审批一行，列为来源页面和操作、提交时间、提交人、来源单据号、状态和当前级别。详情分主表和从表：主表显示来自页面（页面和操作）、来源单据号、提交人、提交时间和当前级别；审批流名称只在从表的"来自审批流"列中显示；从表按 `steps` 每个入口一行，列为级别、审批节点、审批人、来自审批流、状态、处理时间和意见。从表下方按 C09 的 `view` 显示"修改内容"：一张主表，从表按 Tab 显示，列和顺序由审批流配置决定；`before` 与 `after` 不同的单元格显示为"A→B"并高亮，新增行和删除行分别标出；来源单据的每行末尾显示"触发审批"列（行的 `flows`，为空时显示"随审批等待"）。来源单据之后，影响对象每块一个 Tab（`view.affected`），标题为块的 `title`，几个审批流时标题后注明审批流名称；每行最前面是勾选框，表头有全选。
  - 布局草图：[成本核算改价](../草图/审批详情.png)、[物料清单改价（按成本单勾选）](../草图/审批详情-物料清单改价.png)、[一张单据命中两个审批流](../草图/审批详情-多个审批流合并.png)。
- FA-07：当前用户在本级多个入口中待处理时，只显示一个"通过"按钮，点一次即提交；各审批流取消勾选的行一起提交。
- FA-08：通过时，按详情给出的人工参数（C06 7.1 的 `params`）显示输入框，类型为字符串、数值、是非或日期，必填项没填时不能提交。驳回时必须填写驳回原因才能提交，撤回时可以填写原因；驳回和撤回不显示动作参数。详情的从表显示每次处理的原因。
- FA-09："修改内容"中带 `missing` 的行（影响对象的记录已不存在，approval AP-21）整行红底，显示"记录已不存在"，以及 `missing` 中有值的单据号和名称；没有勾选框，表头全选也不选它。

## 4. 依赖

契约 C02、C03、C09、C10、C11。

## 5. 内部流程

打开待办 → 打开详情 → 勾选、填写意见 → 通过或驳回 → 按结果刷新列表。

## 6. 接入方式

注册到外壳（C11），由 assembly 完成。真实联调：批次 D。

## 7. 验收边界

- 开始开发的前置条件：contracts 完成。
- 本模块完成（模拟验证）：用 C09 的样例覆盖勾选、重新确认和撤回按钮的显示。
- 联调后才能确认：两个审批样例从保存触发到最终批准的完整流程（批次 D）。
