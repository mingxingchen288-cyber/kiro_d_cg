# frontend-approval

状态：已确认。上级：[架构与组装](../架构与组装.md)。

## 1. 职责

- 负责：待办列表（我审批的、我发起的）；审批详情（来源的修改前后、各级进度、候选对象及其影响、勾选框、意见）；通过、驳回、撤回；排队和重新确认的提示。
- 不负责：审批的判断和执行（approval）。

## 2. 所有权

| 类别 | 内容 |
|---|---|
| 代码 | `frontend/src/modules/approval/` |
| 状态 | 待办和审批详情的界面状态 |

## 3. 对外契约

导出 C11 的 `FrontendModule`，路由 `/approval`；调用 [C09 第 6 节](../契约/C09-HTTP接口.md)的接口。

- FA-01：只有 `selectable` 为 true 的候选对象显示勾选框；通过时按审批流提交勾选结果，带上结果指纹和新的请求键。
- FA-02：`queuedBehind` 大于 0 时，"通过"不可用，并显示前面还有几个审批。
- FA-03：收到 409 RECONFIRM_REQUIRED 时，重新读取详情，请审批人再次确认。
- FA-04：只有 `canWithdraw` 为 true 时显示"撤回"。
- FA-05：通知中的链接 `/approval/{approvalId}` 直接打开审批详情。
- FA-06：一张单据的审批只显示一次，几个审批流合在一起显示（C09 第 6 节）。待办列表每个审批一行，列为来源页面和操作、提交时间、提交人、来源单据号、状态和当前级别。详情分主表和从表：主表显示来自页面（页面和操作）、来源单据号、提交人、提交时间、当前级别和排队情况；审批流名称只在从表的"来自审批流"列中显示；从表按 `steps` 每个入口一行，列为级别、审批节点、审批人、来自审批流、状态、处理时间和意见。从表下方按 C09 的 `view` 显示"修改内容"：一张主表，从表按 Tab 显示，列和顺序由审批流配置决定；`before` 与 `after` 不同的单元格显示为"A→B"并高亮，新增行和删除行分别标出；来源单据的每行末尾显示"触发审批"列（行的 `flows`，为空时显示"随审批等待"）。从表的行来自候选单据时，同一张单据的行连在一起，`mergedColumns` 中的列合并显示，勾选框在这组行的最前面，表头有全选；只能勾选 `selectable` 为 true 的单据。
  - 布局草图：[成本核算改价](../草图/审批详情.png)、[物料清单改价（按成本单勾选）](../草图/审批详情-物料清单改价.png)、[一张单据命中两个审批流](../草图/审批详情-多个审批流合并.png)。
- FA-07：当前用户在本级多个入口中待处理时，只显示一个"通过"按钮，点一次即提交；有可勾选的候选对象时，各审批流的勾选一起提交。
- FA-08：通过时，按详情给出的人工参数（C06 7.1 的 `params`）显示输入框，类型为字符串、数值、是非或日期，必填项没填时不能提交。驳回时必须填写驳回原因才能提交，撤回时可以填写原因；驳回和撤回不显示动作参数。详情的从表显示每次处理的原因。

## 4. 依赖

契约 C02、C03、C09、C10、C11。

## 5. 内部流程

打开待办 → 打开详情 → 勾选、填写意见 → 通过或驳回 → 按结果刷新列表。

## 6. 接入方式

注册到外壳（C11），由 assembly 完成。真实联调：批次 D。

## 7. 验收边界

- 开始开发的前置条件：contracts 完成。
- 本模块完成（模拟验证）：用 C09 的样例覆盖勾选、排队、重新确认和撤回按钮的显示。
- 联调后才能确认：两个审批样例从保存触发到最终批准的完整流程（批次 D）。
