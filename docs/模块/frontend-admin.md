# frontend-admin

状态：已确认。上级：[架构与组装](../架构与组装.md)。

## 1. 职责

- 负责：账号的列表、高级查询、新建、修改（用户名、姓名、部门、角色、启用或停用）、改密码；部门的列表、高级查询、新建、修改、删除；投递记录的查看和重新排队。
- 不负责：账号和投递的业务规则（identity、delivery）。

## 2. 所有权

| 类别 | 内容 |
|---|---|
| 代码 | `frontend/src/modules/admin/` |

## 3. 对外契约

导出 C11 的 `FrontendModule`，路由 `/admin`；调用 [C09](../契约/C09-HTTP接口.md) 第 2 节和第 7 节的管理接口。

- FM-01：只对管理员角色显示。
- FM-02：停用账号或撤销角色前先确认，并提示该账号会被立即下线。
- FM-03：只有状态为已放弃的投递记录可以重新排队。
- FM-04：命令审查：显示开关和记录列表（C09 第 7a 节），可以按用户和结果筛选，展开查看每条 SQL；关闭开关前确认，提示会清除全部记录。
- FM-05：人员管理的"用户名"列已有的行也能改（同旧系统 user-manage 的"用户名"列，cmx CostUser 的 USERNAME 为 EDITABLE=1）。改了的行点"保存"时带 `username` 提交（C09 v15，没改的不带）；重名时提示"保存失败：账号名 … 已存在"，这一行留在表格里。改名后这个人用新用户名登录（identity 的 ID-11）。"初始密码"仍只有新增的行能填。代码在 `admin/accounts.ts`、`renderers/AccountsPanel.vue`。
- FM-06：人员管理、部门管理的工具栏有"高级查询"，同旧系统两个通用页的 `advancedSearch` 按钮。对话框的样子和交互同 frontend-page 的高级查询（FP-22）和旧系统 `AdvancedSearchDialog.vue`：标题"查询条件"，一打开就列出能查的列（人员：ID、用户名、姓名、部门、状态；部门：ID、部门名称，即旧页面勾了"查询"、新表格上也有的列），每行为隐藏（×）、勾选框和字段名、运算符、值，填了值自动勾上，右上角"显示字段"恢复隐藏的条件，底部"已启用 N 项"、重置、取消、查询；条件之间都是"且"，没有"添加条件"（旧对话框也没有）。运算符同 FP-22：数值 14 个，文本 8 个，部门（从部门列表中选）为等于、不等于、IN、NOT IN、为空、不为空，状态（启用、停用）为等于、不等于；默认运算符文本为"包含"、其他为"等于"。查询时条件经 C09 v15 的 `advanced` 提交，人员管理与关键字一起用（且）；条件下次打开还在，查询后工具栏按钮显示"高级查询（N）"；"重置"清空值和勾选后查全部。模块之间不能互相导入，这份写法在 `admin/advanced-search.ts`、`renderers/AdvancedSearchDialog.vue`，与 frontend-page 的分开维护。
