# C08 后端端口

版本：v2。维护：contracts。状态：已确认。

端口和类型定义在 `backend/src/cost_platform/contracts/` 中：类型在 `types.py`，端口在 `ports.py`。contracts 为每个端口提供内存替代实现（`contracts/fakes/`），并提供一套契约测试（`backend/tests/contracts/`）。真实实现必须通过同一套测试。谁提供、谁使用见[架构第 8 节](../架构与组装.md)。

## 2. db-core 提供

```python
class UnitOfWork(Protocol):
    connection: sqlalchemy.engine.Connection   # 本事务的连接，各模块的存储实现都用它
    def commit(self) -> None: ...
    def rollback(self) -> None: ...

class UnitOfWorkFactory(Protocol):
    def begin(self) -> ContextManager[UnitOfWork]: ...   # 退出时没有提交就回滚

class SchemaInspector(Protocol):
    def columns(self, table: str) -> dict[str, ColumnInfo] | None: ...   # 表不存在时为 None

class ConnectionFactory(Protocol):
    def legacy_readonly(self) -> ContextManager[sqlalchemy.engine.Connection]: ...   # 用 d_cg 账号开启只读事务（SET TRANSACTION READ ONLY），以 CMX.表名 读取旧库；只供 migration 和复制业务表使用
```

- 数值列读出为 `Decimal`，不经过浮点。
- Oracle 错误按 C03 映射：等锁超时为 DOCUMENT_BUSY，连接断开或数据库不可用为 DATABASE_UNAVAILABLE，其余为 INTERNAL_ERROR。

## 6. 管道阶段

write-pipeline 按[架构第 7 节](../架构与组装.md)的顺序调用已注册的阶段。阶段之间只通过 `CommandState` 传递数据。

```python
class PipelineStage(Protocol):
    name: str
    def applies(self, state: CommandState, ctx: ExecutionContext) -> bool: ...
    def run(self, uow: UnitOfWork, state: CommandState, ctx: ExecutionContext) -> None: ...   # 失败时抛 PlatformError

@dataclass
class CommandState:
    command: Command
    involved: list[DocumentRef]
    current: dict[DocumentRef, DocumentData]     # 加锁后读到的当前值
    actions: list[ActionStep]                    # 要执行的动作（C06 的 afterApproval 或操作的 actions）
    candidate: dict[DocumentRef, DocumentData]   # 合并修改并计算后的数据
    effects: list[RuleEffect]                    # C07 的 effects
    changes: ChangePlan                          # 只含有变化的列
    approvals: list[ApprovalState]               # 本命令提交或处理的审批；提交时每张提交审批的单据一个
    notifications: list[NotificationIntent]
    delivery_ids: list[str]
    prompts: list[Prompt]
    skipped: list[SkippedRow]
    pending_documents: set[DocumentRef]          # 提交审批的单据：等待审批的行不写业务表，其余行照常写入（approval AP-01）
    outcome: Literal["saved", "unchanged", "approvalSubmitted", "approvalProcessed"]
```

| 阶段 | 实现模块 | 读取 | 写入 |
|---|---|---|---|
| 操作权限 | authz | `command`、ctx | 无；不通过时抛 PERMISSION_DENIED |
| 确定涉及的单据 | write-pipeline、operations、approval | `command` | `involved`、`actions` |
| 冻结检查 | approval | `involved`、`command`、ctx | 无；命中时抛 FROZEN_BY_APPROVAL，ctx 来源为本审批时放行本审批的冻结 |
| 审批处理 | approval | `current`、`command` | `approvals`、`actions`、`notifications` |
| 动作执行 | operations、write-pipeline、authz、rules-core | `current`、`actions` | `candidate`、`effects`、`changes`、`prompts`、`skipped` |
| 触发审批 | approval | `effects`、`candidate`、`changes` | `approvals`、`pending_documents`、`outcome`、`notifications` |
| 登记通知 | delivery | `notifications` | `delivery_ids` |
| 投递 | delivery | `delivery_ids` | 无；提交后执行 |

判重、加锁并读取、写入变更、审计、写入命令记录并提交，由 write-pipeline 自己完成，不是可注册的阶段。

## 7. authz 提供

```python
class PermissionChecker(Protocol):
    def can_run(self, ctx: ExecutionContext, operation: str, page: str | None) -> bool: ...
    def row_condition(self, ctx: ExecutionContext, page: str, entity: str) -> SqlCondition | None: ...
    # SqlCondition：sql 为行权限的 SQL 条件（占位符已换成绑定变量名），binds 为绑定变量的值；没有行权限时为 None
    def writable_fields(self, ctx: ExecutionContext, page: str, entity: str) -> frozenset[str]: ...
    def can_export(self, ctx: ExecutionContext, page: str, export_code: str) -> bool: ...
```

- 查询时，queries-export 把 `row_condition` 与筛选条件用 AND 组合。
- 写入时，write-pipeline 在加锁读取的同一条 SQL 中，把 `row_condition` 作为判断列一起查出，不另发 SQL；有一行超出范围就拒绝整个命令（403 PERMISSION_DENIED）。
- ctx 来源为审批时，写权限按操作声明的可写字段（C06）判断，不检查行权限和 `writable_fields`。
