# C04 执行上下文

版本：v1。维护：contracts。状态：已确认。

每个 HTTP 请求开始时，由 assembly 的中间件生成一次（[架构 10.1](../架构与组装.md)），之后只读。命令执行期间，上下文和其中的配置快照不变。

```python
@dataclass(frozen=True)
class Identity:
    user_id: str             # 十进制文本（C01）
    username: str
    display_name: str
    department_id: str | None
    role_code: str           # 会话选定的角色；平台只使用这一个角色
    session_id: str

@dataclass(frozen=True)
class Origin:
    kind: Literal["user", "approval"]
    approval_id: str | None  # kind 为 "approval" 时必填

@dataclass(frozen=True)
class ExecutionContext:
    request_id: str          # 小写 UUID，用于日志
    identity: Identity
    config: ConfigSnapshot   # 定义见 C08
    config_version: int      # 写入响应头 X-Config-Version
    origin: Origin
    now: datetime            # 取自 Clock，同一请求内不变
```

规则：

- 用户发起的请求，`origin.kind` 为 `user`。
- 审批的最终批准按审批流通过后的操作（C06 7.7）写入来源单据和受影响单据时，`origin.kind` 为 `approval`，`approval_id` 为该审批。在这个上下文中，写入管道不执行"触发审批"阶段，目标的更新也不再触发同步，即传播边界（[C06](C06-配置模型.md) 的 `propagation`）。目标自身的计算和校验规则照常执行。
- 读取配置快照时，会话和配置分两次读取 Redis：会话由 identity 读，配置由 config 读。
