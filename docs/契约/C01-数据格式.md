# C01 数据格式

版本：v2。维护：contracts。状态：已确认。

适用于全部 HTTP 接口、实时事件、rules-core 的输入输出，以及后端端口中的业务数据。

## 1. JSON 约定

- 接口字段名用 camelCase；业务字段名保持配置中的写法，例如 `QTY`、`ZX_PRICE`。
- 空值用 `null`。在 Patch 的 `changes` 中，出现的字段表示修改，值为 `null` 表示改为空；不出现的字段不修改。
- 接收方只认 camelCase 字段名，出现未定义的字段即拒绝。整数和是非必须是 JSON 的数字和布尔，不接受 `"13"`、`"true"`、`1` 这类写法；日期和日期时间必须是第 4 节的格式，不接受时区后缀、小数秒和时间戳。
- 发送方输出时，契约写明总会出现的字段总是输出，值为空时输出 `null`（例如命令结果中行的 `frozen`）；可选字段没有值时省略（例如已保存的行不带 `clientRowId`）。

## 2. 十进制文本

- 全部精确数值（金额、数量、价格、整数和主键）在 JSON 中都是字符串。
- 格式为 `^-?[0-9]+(\.[0-9]+)?$`，不允许指数、正号、千分位分隔符和空格。
  - 合法：`0`、`-12.30`、`12345678901234567.89`。
  - 不合法：`1e5`、`+1`、`1,000`、`.5`、`5.`、` 1`。
- 解析和格式化都不经过二进制浮点：后端用 Python `Decimal`，前端用 BigInt 表示（整数加小数位数），rules-core 用 `rust_decimal`。
- 末尾零不影响数值是否相等，例如 `1.50` 与 `1.5` 相等。
- 格式不合法时，接收方返回 422 VALIDATION_FAILED（[C03](C03-错误.md)），`details` 定位到字段。

## 3. 数值一致的判定

用于判断两端（例如前端与后端）的计算结果是否一致，不改变字段的存储精度、显示位数和业务舍入规则。

两个数值一致，当且仅当以下三条同时成立：

1. 正负号相同。截断到小数点后 15 位后为零的数值都视为零，不比较正负号，因此 `-0`、`-0.00`、`-0.0000000000000001` 与 `0` 都一致。
2. 整数部分相同。
3. 小数点后前 15 位相同：不足 15 位的末尾补零后比较；第 16 位及以后的差异不影响判定；比较时不四舍五入。

非数值结果（规则结论、行标识、字段名、可编辑和必填状态、文本）必须完全相同；一方为空、另一方为数值时判为不一致。原始 JSON 文本是否逐字节相同，不作为判定条件。

边界样例，契约测试必须全部覆盖：

| 甲 | 乙 | 结论 |
|---|---|---|
| `1.23` | `1.230000000000000` | 一致 |
| `1.2345678901234561` | `1.2345678901234562` | 一致 |
| `0.000000000000001` | `0.000000000000002` | 不一致 |
| `123456789012345.67` | `123456789012345.68` | 不一致 |
| `2.5` | `3.5` | 不一致 |
| `1.5` | `-1.5` | 不一致 |
| `-0`、`-0.00` | `0` | 一致 |
| `-0.0000000000000001` | `0` | 一致 |

## 4. 日期和时间

- 日期：`YYYY-MM-DD`。
- 日期时间：`YYYY-MM-DDTHH:mm:ss`，按服务器时区，不带时区后缀。

## 5. 标识

| 名称 | 格式 | 含义 |
|---|---|---|
| `rowKey` | 主键列的值转成的文本 | 已保存的行 |
| `recordKey` | 同 `rowKey` | 主单，即主表行 |
| `clientRowId` | `tmp-` 加小写 UUID | 前端为新增行生成，在一个页面实例内唯一 |
| `requestKey` | 小写 UUID | 每次提交命令时新生成 |
| `approvalId` | 十进制文本 | 审批 |
| `deliveryId`、`eventId` | 小写 UUID | 投递记录、实时事件 |

业务表都使用单列主键，`rowKey` 和 `recordKey` 就是这一列的值。

## 6. 契约测试

后端（Python）、前端（TypeScript）和 rules-core（Rust）各自实现十进制文本的解析、格式化，以及第 3 节的判定，并用第 2、3 节的样例测试。三端对每个样例的结论必须相同。
