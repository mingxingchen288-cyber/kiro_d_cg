# C02 命令与结果

版本：v9。维护：contracts。状态：v7 已确认；v9 文字与实现对齐，语义不变：第 1 节审批处理命令样例的 `checkedRows` 改成 C09 第 6 节通过请求的写法（`flow`、`block`、`key`，同 contracts 的 `CheckedRow`）。v8 按用户 2026-10-30 同意的"按旧系统做"：新增行加可选的 `copyOf`（复制出的行，第 1 节），复制时勾选的字段不论能不能编辑都写进新行，后端按源行核对；来源为旧系统复制源行全部字段（`cost-web/src/v3/composables/meta-v3/copy-row-fields.ts` 第 23–29 行）、新增行提交全部字段（`useWorkingSetStore.ts` 第 834–876 行）、后端插入只跳过虚拟列（`DynamicDataService.java` 第 274–327 行）。字段名和后端取源行值的做法由实施者决定。v7 中审批通过命令的 `params` 改为带 `checkedRows`（勾选的行），随 C06 v16、C09 v8（用户 2026-10-28）。v5 的死锁返回 DOCUMENT_BUSY 属于实现细节，由实施者决定（架构第 5 节）。

命令是业务数据唯一的写入形式。页面保存和按钮操作经 `POST /api/commands`（[C09](C09-HTTP接口.md)）提交；审批的通过、驳回和撤回由 approval 转成命令后，交给 `CommandExecutor`（[C08](C08-后端端口.md)）。

## 1. 命令

页面保存：

```json
{
  "requestKey": "3f2b6c1e-8a4d-4c2e-9b1a-0d6e5f7a8b9c",
  "page": "COST_PINGGU",
  "operation": "COST_PINGGU.save",
  "documents": [
    {
      "entity": "COST_PINGGU",
      "master": {"op": "modify", "rowKey": "1001", "changes": {"QTY": "12"}},
      "details": [
        {"entity": "COST_MATERIAL", "op": "add", "clientRowId": "tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d", "values": {"GOODSID": "115", "USAGE": "1"}},
        {"entity": "COST_MATERIAL", "op": "modify", "rowKey": "5001", "changes": {"PRICE": "3.60"}},
        {"entity": "COST_MATERIAL", "op": "delete", "rowKey": "5002"}
      ]
    }
  ],
  "params": {}
}
```

审批处理（由 approval 生成）：

```json
{
  "requestKey": "9d8c7b6a-5f4e-4d3c-8b2a-1f0e9d8c7b6a",
  "page": null,
  "operation": "approval.pass",
  "documents": [],
  "params": {"approvalId": "203", "fingerprint": "sha256:5b1e0c6d9a3f47e28b1c6d0e9f3a2b4c5d6e7f8091a2b3c4d5e6f708192a3b4c", "checkedRows": [{"flow": "GOODS_TO_COST", "block": "costMaterial", "key": "206323"}], "comment": "价格已核对", "params": {"effectiveDate": "2026-11-01"}}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `requestKey` | 小写 UUID（[C01](C01-数据格式.md)） | 必填，每次提交新生成 |
| `page` | 字符串或 null | 发起命令的页面；审批处理为 null |
| `operation` | 字符串 | 操作编码（[C06](C06-配置模型.md)）。页面保存用页面视图的 `saveOperation`；审批处理为 `approval.pass`、`approval.reject` 或 `approval.withdraw` |
| `documents` | 数组 | 本次修改的单据，每张单据一项。只有页面保存带修改；按钮操作和审批处理为空数组 |
| `documents[].entity` | 字符串 | 主表实体 |
| `documents[].master.op` | `add`、`modify`、`delete`、`none` | `none` 表示主表不改、只改明细 |
| `documents[].master.rowKey` | 文本 | `add` 时不填，改填 `clientRowId` |
| `documents[].master.changes` | 对象 | `modify` 时只含修改的字段 |
| `documents[].master.values` | 对象 | `add` 时为填写的字段 |
| `documents[].master.copyOf` | 文本，可省略 | `add` 时可写：这一行是复制出来的，值为源行（同一实体）的主键，例如 `{"op": "add", "clientRowId": "tmp-…", "copyOf": "200721", "values": {"GOODSID": "392", "PROJECTNO": "P-01"}}`。明细的 `add` 同样可写，源行为同一明细实体的行 |
| `documents[].details[]` | 数组 | 明细的新增、修改、删除，`op` 取 `add`、`modify`、`delete`，字段规则同主表 |
| `params` | 对象 | 操作参数，内容由执行该操作的模块校验（按钮操作为 operations，审批处理为 approval）。按钮操作的选中行为 `{"selectedRows": [{"entity": "…", "rowKey": "…"}]}`；审批处理见上例，其中 `params.params` 为审批人通过时填写的人工参数（C09 通过请求的 `params`） |

规则：

- 只有页面保存把前端的修改传给后端。一次保存把编辑缓冲中的全部修改作为一个命令提交，在一个事务内全部成功或全部失败；`changes`、`values` 只含用户填写的字段，计算字段由后端计算（见下面的不可写字段）。
- 按钮操作只传选中行的主键（`params.selectedRows`），`documents` 必须为空数组，否则返回 400 INVALID_REQUEST。后端按主键加锁读取数据库中的当前数据，按它执行，不使用前端显示的值：前端的值可能已经过时，行也可能已被别人删除。选中的行已不存在时，按操作的 `rowNotFound` 处理（C06 第 4 节）：`skip` 跳过这一行并写入结果的 `skipped`，`reject` 返回 409 ROW_NOT_FOUND。前端按命令结果的 `rows` 刷新受影响的行。
- 审批按单据判断：一张单据中有行使某个审批流第 1 级的节点成立（审核操作选中的表格和操作，逐行判断入口条件，C06 7.3）时，这张单据提交审批并整张冻结，本次对它的全部修改都不写业务表；其余单据照常写入（[approval](../模块/approval.md) AP-01）。
- `changes` 和 `values` 中不得出现计算字段、只读的 ERP 列（C06 第 2 节）、`erpRow.column`、主键和主从关联字段；出现即拒绝整个命令。复制出的行（带 `copyOf`）例外见下一条。
- 复制出的行：`values` 为复制时勾选的字段，不论能不能编辑都写（例如成本单的币种、项目号），没勾选的可写字段写 null。后端按 `copyOf` 读出源行（按用户能读的范围：主表行满足行权限，明细行所属的主表行满足行权限），可写的字段取 `values` 中的值；不可写、但用户在页面上能看到、能写进表的字段取源行的值，不用 `values` 中的值；计算字段和只在视图中的字段不写；其余不可写的字段照常拒绝。复制出的行不补默认值。源行已不存在或超出行权限时返回 409 ROW_NOT_FOUND。见 write-pipeline 的 WP-21。
- 删除主表行表示连同它的全部明细一起删除，`details` 中不必列出这些明细。
- 内容摘要：对去掉 `requestKey` 的命令体，按键名排序、去掉空白后取 SHA-256，用于判重。

## 2. 命令结果

已写入：

```json
{
  "requestKey": "3f2b6c1e-8a4d-4c2e-9b1a-0d6e5f7a8b9c",
  "outcome": "saved",
  "rows": [
    {"entity": "COST_PINGGU", "rowKey": "1001", "values": {"DOCID": "1001", "QTY": "12", "TOTAL_COST": "54.00"}, "frozen": null},
    {"entity": "COST_MATERIAL", "rowKey": "7001", "clientRowId": "tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d", "values": {"DTLID": "7001", "GOODSID": "115", "USAGE": "1", "PRICE": "1.20"}, "frozen": null},
    {"entity": "COST_MATERIAL", "rowKey": "5002", "deleted": true}
  ],
  "idMap": {"tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d": "7001"},
  "prompts": [{"rule": "R_MARGIN_LOW", "message": "毛利率低于 5%", "entity": "COST_PINGGU", "rowKey": "1001", "field": "MARGIN"}],
  "skipped": [{"entity": "COST_MATERIAL", "rowKey": "5003", "reason": "ROW_NOT_FOUND"}],
  "approvals": []
}
```

已提交审批：

```json
{
  "requestKey": "7c1d2e3f-4a5b-4c6d-8e7f-9a0b1c2d3e4f",
  "outcome": "approvalSubmitted",
  "rows": [
    {"entity": "COST_PINGGU", "rowKey": "1001", "values": {"DOCID": "1001", "QTY": "10", "TOTAL_COST": "45.00"}, "frozen": {"approvalId": "203"}}
  ],
  "idMap": {},
  "prompts": [],
  "skipped": [],
  "approvals": [{"approvalId": "203", "document": {"entity": "COST_PINGGU", "recordKey": "1001"}, "status": "pending", "level": 1, "flows": ["COST_TO_GOODS"]}]
}
```

| 字段 | 说明 |
|---|---|
| `outcome` | `saved`：已写入；`unchanged`：提交的值与当前值相同，没有写入；`approvalSubmitted`：有单据提交了审批，这些单据本次的修改都没有写入，其余单据已写入；`approvalProcessed`：审批处理已记录 |
| `rows` | 受影响的行：本次写入的行、计算带出变化的行和删除的行。每行给出该实体的全部字段，字段可见性由前端处理。提交审批的单据中，被修改和删除的行给出正式值；新增的行还没有写入，不在其中 |
| `rows[].frozen` | 所在单据被冻结时给出冻结它的审批；未冻结为 null |
| `idMap` | 临时编号到正式主键的对应，覆盖本命令的每条新增行。等待审批的新增行在提交时已取得正式主键（approval AP-02），也在这里给出，审批通过后才写入 |
| `prompts` | 规则提示：`rule`、`message`，以及定位用的 `entity`、`field` 和 `rowKey`（新增行为 `clientRowId`），定位字段可以省略 |
| `skipped` | 因行已被删除而跳过的修改 |
| `approvals` | 本命令提交或处理的审批，没有时为空数组。提交时每张提交审批的单据一项，处理时只有被处理的审批一项。每项给出审批编号、单据（`entity` 和 `recordKey`）、状态（`pending`、`approved`、`rejected`、`withdrawn`）、当前级别和命中的审批流编码 |

## 3. 错误

失败的命令整笔回滚，不留下命令记录；错误体和状态码见 [C03](C03-错误.md)。

| 情况 | 结果 |
|---|---|
| 同一用户、同一请求键已完成，内容摘要相同 | 返回原结果，不是错误 |
| 同一请求键，内容摘要不同 | 422 IDEMPOTENCY_KEY_REUSED |
| 同一请求键仍在处理，等待超时 | 409 REQUEST_IN_PROGRESS |
| 缺少请求键或不是 UUID | 400 INVALID_REQUEST |
| Patch 含不可写的字段 | 422 FIELD_NOT_WRITABLE |
| 必填为空、格式不合法 | 422 VALIDATION_FAILED |
| 规则拒绝 | 422 RULE_REJECTED |
| 数据被审批冻结 | 409 FROZEN_BY_APPROVAL |
| 等待单据锁超时，或与其他命令互相等锁形成死锁 | 409 DOCUMENT_BUSY |
| 要修改的行已被删除，且配置为拒绝 | 409 ROW_NOT_FOUND |
| 复制出的行的源行已不存在或超出行权限 | 409 ROW_NOT_FOUND |
| 无权执行操作，或修改超出行权限 | 403 PERMISSION_DENIED |
