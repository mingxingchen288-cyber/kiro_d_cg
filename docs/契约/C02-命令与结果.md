# C02 命令与结果

版本：v2。维护：contracts。状态：已确认。

命令是业务数据唯一的写入形式。页面保存和按钮操作经 `POST /api/commands`（[C09](C09-HTTP接口.md)）提交；审批的通过、驳回和撤回由 approval 转成命令后，交给 `CommandExecutor`（[C08](C08-后端端口.md)）。

## 1. 命令

页面保存：

```json
{
  "requestKey": "3f2b6c1e-8a4d-4c2e-9b1a-0d6e5f7a8b9c",
  "page": "COST_PINGGU",
  "operation": "COST_PINGGU.save",
  "documents": [
    {
      "entity": "COST_PINGGU",
      "master": {"op": "modify", "rowKey": "1001", "changes": {"QTY": "12"}},
      "details": [
        {"entity": "COST_MATERIAL", "op": "add", "clientRowId": "tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d", "values": {"GOODSID": "115", "USAGE": "1"}},
        {"entity": "COST_MATERIAL", "op": "modify", "rowKey": "5001", "changes": {"PRICE": "3.60"}},
        {"entity": "COST_MATERIAL", "op": "delete", "rowKey": "5002"}
      ]
    }
  ],
  "params": {}
}
```

审批处理（由 approval 生成）：

```json
{
  "requestKey": "9d8c7b6a-5f4e-4d3c-8b2a-1f0e9d8c7b6a",
  "page": null,
  "operation": "approval.pass",
  "documents": [],
  "params": {"approvalId": "203", "fingerprint": "sha256:5b1e…", "selectedObjects": [{"flow": "GOODS_TO_COST", "entity": "COST_PINGGU", "recordKey": "2550"}], "comment": "价格已核对"}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `requestKey` | 小写 UUID（[C01](C01-数据格式.md)） | 必填，每次提交新生成 |
| `page` | 字符串或 null | 发起命令的页面；审批处理为 null |
| `operation` | 字符串 | 操作编码（[C06](C06-配置模型.md)）。页面保存用页面视图的 `saveOperation`；审批处理为 `approval.pass`、`approval.reject` 或 `approval.withdraw` |
| `documents` | 数组 | 本次修改的单据，每张单据一项；按钮操作和审批处理可以为空 |
| `documents[].entity` | 字符串 | 主表实体 |
| `documents[].master.op` | `add`、`modify`、`delete`、`none` | `none` 表示主表不改、只改明细 |
| `documents[].master.rowKey` | 文本 | `add` 时不填，改填 `clientRowId` |
| `documents[].master.changes` | 对象 | `modify` 时只含修改的字段 |
| `documents[].master.values` | 对象 | `add` 时为填写的字段 |
| `documents[].details[]` | 数组 | 明细的新增、修改、删除，`op` 取 `add`、`modify`、`delete`，字段规则同主表 |
| `params` | 对象 | 操作参数。按钮操作的选中行为 `{"selectedRows": [{"entity": "…", "rowKey": "…"}]}`；审批处理见上例 |

规则：

- 一次保存把编辑缓冲中的全部修改作为一个命令提交，在一个事务内全部成功或全部失败。
- 审批按单据判断：命中审批的单据，操作在命中审批流 `trigger.operations` 中的行（默认只有修改）提交审批、不写业务表，其余行落在本审批冻结范围内的也随审批等待，不在范围内的照常写入；其余单据照常写入（[approval](../模块/approval.md) AP-01）。
- `changes` 和 `values` 中不得出现计算字段、只读的 ERP 列（C06 第 2 节）、`erpRow.column`、主键和主从关联字段；出现即拒绝整个命令。
- 删除主表行表示连同它的全部明细一起删除，`details` 中不必列出这些明细。
- 内容摘要：对去掉 `requestKey` 的命令体，按键名排序、去掉空白后取 SHA-256，用于判重。

## 2. 命令结果

已写入：

```json
{
  "requestKey": "3f2b6c1e-8a4d-4c2e-9b1a-0d6e5f7a8b9c",
  "outcome": "saved",
  "rows": [
    {"entity": "COST_PINGGU", "rowKey": "1001", "values": {"DOCID": "1001", "QTY": "12", "TOTAL_COST": "54.00"}, "frozen": null},
    {"entity": "COST_MATERIAL", "rowKey": "7001", "clientRowId": "tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d", "values": {"DTLID": "7001", "GOODSID": "115", "USAGE": "1", "PRICE": "1.20"}, "frozen": null},
    {"entity": "COST_MATERIAL", "rowKey": "5002", "deleted": true}
  ],
  "idMap": {"tmp-6a1f2c3d-0b4e-4f5a-8c7d-9e0f1a2b3c4d": "7001"},
  "prompts": [{"rule": "R_MARGIN_LOW", "message": "毛利率低于 5%", "entity": "COST_PINGGU", "rowKey": "1001", "field": "MARGIN"}],
  "skipped": [{"entity": "COST_MATERIAL", "rowKey": "5003", "reason": "ROW_NOT_FOUND"}],
  "approvals": []
}
```

已提交审批：

```json
{
  "requestKey": "…",
  "outcome": "approvalSubmitted",
  "rows": [
    {"entity": "COST_PINGGU", "rowKey": "1001", "values": {"DOCID": "1001", "QTY": "10", "TOTAL_COST": "45.00"}, "frozen": {"approvalId": "203", "fields": []}}
  ],
  "idMap": {},
  "prompts": [],
  "skipped": [],
  "approvals": [{"approvalId": "203", "document": {"entity": "COST_PINGGU", "recordKey": "1001"}, "status": "pending", "level": 1, "flows": ["COST_TO_GOODS"]}]
}
```

| 字段 | 说明 |
|---|---|
| `outcome` | `saved`：已写入；`unchanged`：提交的值与当前值相同，没有写入；`approvalSubmitted`：有单据提交了审批，这些单据中等待审批的行没有写入，其余内容已写入；`approvalProcessed`：审批处理已记录 |
| `rows` | 受影响的行：本次写入的行、计算带出变化的行和删除的行。每行给出该实体的全部字段，字段可见性由前端处理。提交审批的单据中，等待审批的修改行和删除行给出正式值；等待审批的新增行还没有写入，不在其中 |
| `rows[].frozen` | 被冻结时给出冻结它的审批和字段（字段为空表示全部字段）；未冻结为 null |
| `idMap` | 临时编号到正式主键的对应，覆盖本命令的每条新增行。等待审批的新增行在提交时已取得正式主键（approval AP-02），也在这里给出，审批通过后才写入 |
| `prompts` | 规则提示 |
| `skipped` | 因行已被删除而跳过的修改 |
| `approvals` | 本命令提交或处理的审批，没有时为空数组。提交时每张提交审批的单据一项，处理时只有被处理的审批一项。每项给出审批编号、单据（`entity` 和 `recordKey`）、状态（`pending`、`approved`、`rejected`、`withdrawn`）、当前级别和命中的审批流编码 |

## 3. 错误

失败的命令整笔回滚，不留下命令记录；错误体和状态码见 [C03](C03-错误.md)。

| 情况 | 结果 |
|---|---|
| 同一用户、同一请求键已完成，内容摘要相同 | 返回原结果，不是错误 |
| 同一请求键，内容摘要不同 | 422 IDEMPOTENCY_KEY_REUSED |
| 同一请求键仍在处理，等待超时 | 409 REQUEST_IN_PROGRESS |
| 缺少请求键或不是 UUID | 400 INVALID_REQUEST |
| Patch 含不可写的字段 | 422 FIELD_NOT_WRITABLE |
| 必填为空、格式不合法 | 422 VALIDATION_FAILED |
| 规则拒绝 | 422 RULE_REJECTED |
| 数据被审批冻结 | 409 FROZEN_BY_APPROVAL |
| 等待单据锁超时 | 409 DOCUMENT_BUSY |
| 要修改的行已被删除，且配置为拒绝 | 409 ROW_NOT_FOUND |
| 无权执行操作，或修改超出行权限 | 403 PERMISSION_DENIED |

## 4. 契约测试

本文每个样例都能被后端模型和前端类型无损解析；去掉 `requestKey` 后内容相同的两个命令，内容摘要相同。
