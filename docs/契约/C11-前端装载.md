# C11 前端装载

版本：v3。维护：contracts。状态：v1 已确认；v2 随 frontend-page 的 FP-19（用户 2026-10-30 同意通用页面加"自定义导出"，行为同旧系统）：`HttpClient.download` 除文件内容外还给出响应头 `Content-Disposition`（`DownloadedFile`），前端按旧系统 `cost-web/src/service/api/export-config.ts` 第 47–59 行从中取下载文件名；v1 只返回文件内容，拿不到文件名。v3 为盘点（`.reports/inventory-20261030/甲-任务卡核对.md` 第四节 B2、第五节 U1）列出的旧系统在用、新平台没有的两项，用户 2026-10-30 回复"其它无异议"同意按旧系统补：
- frontend-page 的路由 `/page/:pageCode` 接受查询参数 `record`（要定位的单据主键），由旧系统通知中心"原单据"跳转时带的 `focusId` 推出（`cost-web/src/layouts/modules/global-header/components/approval-notification-center.vue` 第 141–158 行；页面打开后加主键条件查询、选中这一行、显示明细，再清掉条件，`v3/composables/meta-v3/useWorkingSetStore.ts` 第 255–262 行、`v3/components/MasterDetailLayoutV3.vue` 第 428–460 行）。`tabs.open` 的 `path` 因此可以带查询参数。
- `ShellApi` 增加 `bell`：顶栏铃铛的角标为待我审批的审批数（旧系统 `ApprovalNotificationService.summary` 第 49 行 `unreadCount = approvalCount`），模块处理了审批后调用 `bell.refresh()`，外壳重新读取（旧系统处理完立即 `loadSummary`）。外壳不能导入 frontend-approval（架构第 3 节第 3 条），所以经 `ShellApi` 通知。

frontend-shell 提供外壳和下面的 `ShellApi`；frontend-page、frontend-config、frontend-approval、frontend-admin 各导出一个 `FrontendModule`。assembly 的 `frontend/src/main.ts` 创建 `ShellApi` 依赖的客户端，再把各模块注册到外壳（[架构 6.2](../架构与组装.md)）。

```ts
// frontend/src/contracts/shell.ts
export interface ShellApi {
  http: HttpClient                 // 按 C09 实现：带 Cookie 和 X-CSRF-Token，按 C03 抛出错误，可以把请求标为后台请求（C09 第 1 节）
  realtime: RealtimeClient         // 按 C10 实现：subscribe(pages)、onEvent(topic, handler)
  calc: CalcWorkerClient           // 按 C07 实现：load(pack)、evaluate(handle, request)
  session: {
    user: Readonly<Ref<CurrentUser | null>>
    role: Readonly<Ref<RoleRef | null>>
    configVersion: Readonly<Ref<number>>
  }
  tabs: {
    open(path: string, title: string): void        // v3：path 可以带查询参数，例如 /page/COST_PINGGU?record=2550；页签仍按路径区分，已打开的页签换到这个地址
    close(path: string): void
    setDirty(path: string, dirty: boolean): void   // 有未保存修改时，关闭页签前确认
  }
  message: { success(text: string): void; warning(text: string): void; error(text: string): void }
  bell: { refresh(): void }        // v3：顶栏铃铛的角标（待我审批数，C09 v14 GET /api/approvals?box=todo 的条数）；处理了审批后调用，外壳重新读取
}

export interface FrontendModule {
  name: 'page' | 'config' | 'approval' | 'admin'
  routes: RouteRecordRaw[]         // vue-router 路由，路径前缀见下表
  install(shell: ShellApi): void   // 注册时调用一次
}

// HttpClient 中返回文件的接口（C09 第 4 节的导出）：POST 请求体，响应为文件内容和 Content-Disposition 响应头
export interface DownloadedFile {
  blob: Blob
  contentDisposition: string | null   // 响应头原文，例如 attachment; filename*=UTF-8''%E7%89%A9…；没有这个头时为 null
}
// HttpClient.download(path, body, options?): Promise<DownloadedFile>   （v2；v1 为 Promise<Blob>）
```

| 模块 | 路由前缀 | 菜单来源 |
|---|---|---|
| frontend-page | `/page/:pageCode`；v3 起可带 `?record=<主键>` | `GET /api/me` 返回的菜单中，类型为 `page` 的项；带 `record` 的地址来自审批待办的"原单据" |
| frontend-config | `/config` | 类型为 `config` 的项，只对管理员角色出现 |
| frontend-approval | `/approval` | 外壳固定入口"待办"，以及通知中的链接 |
| frontend-admin | `/admin` | 类型为 `admin` 的项，只对管理员角色出现 |

规则：

- 外壳负责布局、登录、选角色、菜单、页签缓存和主题；模块不直接修改外壳的状态，只通过 `ShellApi` 调用。
- 模块之间不互相导入；跨模块跳转只用路由路径，例如通知链接 `/approval/203`、原单据 `/page/COST_PINGGU?record=2550`。
- `/page/:pageCode?record=<主键>`（v3）：主表只显示这张单据并选中它，明细显示这张单据；页面写明"只显示单据 2550"，用户再查询、排序、筛选或点"显示全部"后照常显示全部。`record` 用过就从地址中去掉，切回这个页签时不再定位。单据不存在或不在当前角色的行权限内时主表为空并提示。
- `bell.refresh()`（v3）：frontend-approval 在通过、驳回、撤回成功后调用。外壳另在会话就绪、收到链接为 `/approval/…` 的站内通知、点开铃铛时，以及每 60 秒（同旧系统）重新读取角标。

契约测试：用 `ShellApi` 的模拟实现装载每个模块，确认路由注册成功，`install` 只依赖 `ShellApi`。模拟实现的 `bell.refresh` 记下调用次数（v3）。模拟实现的 `download` 与其他接口一样按（方法、路径模板）返回预设的响应，导出接口默认返回空的 xlsx 文件和 `attachment; filename*=UTF-8''export.xlsx`（`frontend/tests/contracts/fakes.test.ts`）。
