# C05 页面视图

版本：v8。维护：contracts。状态：待确认（v5、v8）。v4 随 C06 v18（由旧系统 SUMMARY_CONFIG 功能推出）：字段带出页面配置的 `aggregate`（汇总行求和）。v5（2026-10-30，由旧系统成本核算主表产品 Lookup 推出：旧前端回填不看目标列能否编辑，旧后端照样写库）：字段加 `fillWritable`，标出不能直接填写、但随 Lookup 回填写库的字段。v8 随 C06 v24，依据用户 2026-10-30 原话"权限可以按照新增 删除 修改 保存 这样给吗？控制到明细级别"：区域加 `canModify`；区域的新增、删除按钮按 `<区域>:addRow`、`<区域>:deleteRow` 授权，`systemButtons` 不再给出 `addRow`、`deleteRow`。字段名 `canModify` 由实施者决定。

config 在保存配置时，按（页面、角色）生成页面视图。前端经 `GET /api/pages/{pageCode}/view`（[C09](C09-HTTP接口.md)）读取，后端经配置快照（[C08](C08-后端端口.md)）读取。同一（页面、角色、版本）的内容不变。

样例中的角色在成本核算页有保存、高级查询、主表的复制和同步价格、材料的新增、复制、删除和修改，没有主表的新增、删除、修改：主表已经保存的行不能改，复制出的主表行可以填写；材料的已有行可以改。

| 字段 | 说明 |
|---|---|
| `layout` | `single`：单表页，`details` 为空；`masterDetail`：主从页 |
| `detailMode` | 明细的默认显示方式，`tabs` 或 `stack`；用户自己的选择存在个人配置里（C09） |
| `audit` | 本页面的命令是否记录审计差异 |
| `fields[].type` | `text`、`number`、`date`、`datetime`、`boolean` |
| `fields[].scale` | 数值的显示小数位，只用于显示，不改变计算和保存的值；非数值为 null |
| `fields[].source` | `erp`：ERP 列；`own`：平台自有列 |
| `master.erpRow`、`details[].erpRow` | 实体的 ERP 行标识（C06 第 2 节），没有时省略。有时前端在该列等于 `value` 的行上把 ERP 列显示为只读，其他行按 `editable` |
| `fields[].visible`、`editable`、`required` | 实体、页面（含主表区或明细区、Tab）和角色三层叠加后的结果：可见、可编辑只能收紧，必填只能增加。`editable` 再与页面保存操作（`saveOperation`）的 `writableFields` 取交集：不在其中的字段为 false。后端保存时同样只允许写 `writableFields` 中的字段（C06 第 4 节、authz 的 AZ-04），所以页面上显示能编辑的字段，保存时一定能写；能写但不能直接填写的 Lookup 回填目标见 `fillWritable` |
| `fields[].width`、`pinned` | 默认列宽和固定位置（`left`、`right` 或 null）；个人列配置由前端叠加 |
| `fields[].dictType` | 字典类型，值从字典下拉中选 |
| `fields[].lookup` | 写法同 C06 第 3 节的 `lookup`：编码、回填映射（键为本页字段，值为 Lookup 结果的列），以及 `multiple`、`filter`、`fillBack`；后三项为默认值（`false`、无、`true`）时省略 |
| `fields[].fillWritable` | 字段不可编辑（`editable` 为 false），但它是本区域某个可编辑字段的 Lookup 回填目标（`fillBack` 为 true），有写入列，并且在 `writableFields` 中时为 true；否则省略。用户不能直接填写这个字段，Lookup 回填和复制带来的值由前端写进命令，后端按 authz 的 AZ-04 接受。例：成本核算主表的产品名称随产品ID 的产品 Lookup 回填，旧系统照样写库；明细的物料名称只在视图中（`column` 为 null），不是 |
| `fields[].aggregate` | 取自页面配置（C06 第 3 节）：`sum` 为这一列在表格底部的汇总行中求和；没有设置时省略。主表区的和由列表接口的 `aggregates` 给出（C09 第 4 节），明细区由前端对当前单据的明细行求和 |
| `grid` | AG Grid 企业版选项：侧边栏、框选、分组字段 |
| `formLayout` | 24 列网格：`x` 从 0 起，`x + w` 不超过 24，`w`、`h` 不小于 1；为空时按字段顺序排列 |
| `master.buttons`、`details[].buttons` | 本区域中当前角色有权限的按钮，按页面配置的顺序。`key` 为权限键（C06 第 8 节），角色有这个键或 `*` 时才出现；`action` 为内置动作 `addRow`、`deleteRow`、`copyRow`、`saveGridConfig`，或业务动作（`operation` 给出引用的操作）。新增、删除也按区域授权（v8）：`addRow`、`deleteRow` 只出现在页面配置放了它们、角色有 `<区域>:addRow`、`<区域>:deleteRow` 的区域；`requiresSelection` 为 true 时没有选中行就不可用。内置动作的 `requiresSelection` 按 config 的 CF-03 给出，业务动作的取页面配置中的值 |
| `master.canModify`、`details[].canModify` | v8：当前角色能否修改本区域已经保存的行，即角色有没有 `<区域>:modify` 或 `*`（C06 第 8 节）。为 false 时这些行的全部字段都不能编辑，字段的 `editable`、列权限和界面规则都不能把它们放开；新增的行、复制出的行不受影响，按 `fields[].editable` 填写。为 true 时省略。后端按同一规则拒绝（authz 的 AZ-01） |
| `systemButtons` | 当前角色有权限的页面级按钮：`save`、`advancedSearch`；没有 `save` 时整页只读。v8 之前生成的页面视图里还可能有 `addRow`、`deleteRow`，读取时照样接受，前端不用；下次保存任何配置时，config 按 v8 重新生成全部页面视图（CF-02） |

规则：

- 字段可见性只用于显示：后端返回的行包含不可见字段，由前端隐藏；查询、筛选、排序和高级查询只能使用可见字段。
- 个人层（列宽、顺序、固定、显隐和明细显示方式）不在页面视图里，经 C09 的个人配置接口单独读写。
- 前端按 `rulesPack` 下载规则包（[C07](C07-规则内核接口.md)）。
- 按钮和 `canModify` 只用于显示；保存、新增、修改、删除、复制和按钮操作的权限都由后端再检查一次（C06 第 8 节）。

契约测试：本文样例能被后端模型和前端类型无损解析；`formLayout` 越界的样例被 config 拒绝。
