# 搜索代码和文档的方式

用户要求（2026-10-29）：“每次都要搜索很久……能不能超时后换一种方式搜索”。

原因：工作区有四个文件夹（`kiro_d_cg`、`my-project`、`lims三环境`、`接口相关`），`grep_search` 每次扫全部，会扫进 `node_modules`、`target`、`接口相关\.tools\docx-render-runtime` 这类大目录，而且这个工具没有超时参数。

## 默认做法

1. 在 `d:\chonggou\kiro_d_cg` 里搜索，用 `execute_pwsh` 跑 `git grep`，`timeout` 设 30000：

   ```powershell
   git -C 'd:\chonggou\kiro_d_cg' grep -n -I -E '<正则>' -- ':!.reports'
   ```

   `git grep` 只搜纳入版本管理的文件，自动跳过 `node_modules`、`target`、`dist`、`.reports`。需要限定目录时把路径写在 `--` 后面，例如 `-- rules-core backend/src`。

2. 搜不纳入版本管理的内容（`.reports`、生成的产物）时，对指定目录用 `Select-String`，同样设 30 秒超时：

   ```powershell
   Get-ChildItem 'd:\chonggou\kiro_d_cg\.reports\approval-design' -Recurse -File -Include *.md,*.txt | Select-String -Pattern '<正则>'
   ```

3. 搜旧项目 `D:\chonggou\my-project` 时，先确定子目录（例如 `cost-web\src`、后端源码目录），再用 `git -C` 或 `Select-String` 只搜那个子目录，不扫 `node_modules`。

4. `grep_search` 只在确实需要跨多个工作区文件夹时用，而且 `includePattern` 必须限定到具体目录（例如 `rules-core/**`），不用 `**/*` 这类全量模式。

## 超时或太慢时

- 不原样重试同一个搜索。
- 先缩小目录或文件类型；还不行就换成上面另一种方法。
- 连续两次超时，告诉用户在搜什么、搜了哪些目录。
