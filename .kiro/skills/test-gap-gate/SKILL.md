# Test Gap Gate - 测试间隙门控

## 概述

Test Gap Gate 是一个 PreToolUse 钩子技能，它在文件编辑、写入或执行 shell 命令之前强制进行代码分析。与传统的自我评估不同，它要求具体的调查事实，从而提高代码变更的质量。

## 核心概念

LLM 的自我评估往往不可靠，但强制进行具体的调查可以显著改善输出质量。A/B 测试显示，使用此技能可以使代码质量平均提高 +2.25 分。

## 使用场景

- 在影响多个模块的代码库中工作
- 处理具有特定模式或日期的数据文件
- 团队中 AI 生成的代码必须匹配现有模式
- 任何 Claude 倾向于猜测而不是调查的工作流程

## 门控类型

### 编辑门控（每个文件的第一次编辑）

在编辑代码文件之前，必须提供以下事实：

1. **列出所有导入/需要此文件的文件**（搜索整个树结构）
2. **列出受此变更影响的公共函数/类**
3. **如果此文件读写数据文件，显示字段名称、结构和日期格式**（使用脱敏或合成值）
4. **逐字引用用户当前指令**

### 写入门控（第一次新文件创建）

在创建新代码文件之前，必须提供以下事实：

1. **命名将调用此新文件的文件和行**
2. **确认没有现有文件提供相同的功能**（搜索整个树结构）
3. **如果此文件读写数据文件，显示字段名称、结构和日期格式**
4. **逐字引用用户当前指令**

### 破坏性 Shell 门控（每个破坏性命令）

在执行破坏性命令前，必须提供以下事实：

1. **列出此命令将修改或删除的所有文件/数据**
2. **编写一行回滚程序**
3. **逐字引用用户当前指令**

## 安装和配置

将此技能文件复制到 `.kiro/skills/test-gap-gate/` 目录即可安装。

要创建对应的钩子，使用以下命令创建 PreToolUse 钩子：

```bash
# 创建编辑/写入门控钩子
kiro create-hook --name "Test Gap Gate" --trigger PreToolUse --matcher "fs_write|str_replace|fs_append|execute_pwsh" --command "echo 检查门控条件"

# 或者通过 Kiro 界面创建
```

## 环境变量

- `TEST_GAP_GATE_EXEMPT_PATTERNS`: 豁免检查的文件模式
- `TEST_GAP_GATE_MAX_DENIALS`: 最大拒绝次数（可选）
- `TEST_GAP_GATE_METRICS_ENABLED`: 启用指标收集

## 最佳实践

1. **顺序依赖编辑**：将相关编辑发送到尚未触及的文件时，请按顺序发送，不要并行批处理
2. **调查优先**：在门控拒绝后，先进行调查，然后重试被拒绝的编辑
3. **文件重读**：重试编辑后，重新读取文件再继续构建
4. **敏感文件特殊处理**：对认证、支付、迁移等敏感路径使用更严格的门控
